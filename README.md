# Навигатор вёрстки

Учебный сайт Проектной школы ОмГТУ «Веб-разработка». Он ведёт команды по шагам от макета в Figma до готовой главной страницы. В каждом шаге есть цель и время, мини-теория, разминка с автопроверкой, задание для своего сайта, подсказки, чек-лист и раздел «Частые ошибки».

Сайт собран на [Astro](https://astro.build/) + [Starlight](https://starlight.astro.build/). Шаги лежат в обычных текстовых файлах `.mdx`, поэтому, чтобы добавить или поправить шаг, программировать не нужно.

---

## Запуск на своём компьютере

Нужен [Node.js](https://nodejs.org/) версии 22 или новее (кнопка LTS на сайте).

```bash
npm install      # один раз: скачать зависимости
npm run dev      # запустить сайт → http://localhost:4321/
```

Сайт обновляется сам, когда вы сохраняете файл. Остановить: Ctrl+C в терминале.

Проверить, что всё собирается без ошибок (то же делает GitHub перед публикацией):

```bash
npm run build    # готовый сайт появится в папке dist/
npm run preview  # посмотреть собранную версию
```

## Публикация на GitHub Pages

Публикует GitHub Actions: после каждого изменения в ветке `main` сайт пересобирается сам. Настройка нужна один раз:

1. Создайте на GitHub репозиторий (например, `navigator`) и загрузите в него этот проект.
2. В репозитории откройте **Settings → Pages**. В поле **Source** выберите **GitHub Actions**.
3. Откройте вкладку **Actions**. Через 1–2 минуты там будет зелёная галочка у «Публикация на GitHub Pages».
4. Сайт откроется по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`.

Адрес подставляется сам (файл `.github/workflows/deploy.yml`). Исключение — репозиторий с именем `<логин>.github.io`: для него в `deploy.yml` уберите строку `BASE_PATH`.

Красный крестик в Actions значит, что сборка упала. Откройте запуск: в логе написано, в каком файле ошибка, чаще всего это опечатка в верхней части шага.

## Как добавить новый шаг

Пример: пишем шаг «Бургер-меню» для занятия 6. Заглушки шагов занятий 6–7 уже лежат в папках `src/content/docs/lesson-6/` и `lesson-7/`, их можно дописывать.

Список занятий (номер, название, результат) лежит в `src/data/route.json`. Новое занятие — новая строка там и новая папка `lesson-N`: боковое меню и маршрут подхватят её сами.

**1. Скопируйте образец.** Файл `templates/step.mdx` скопируйте в папку занятия и переименуйте:

```
src/content/docs/lesson-2/2-3-box-model.mdx
```

Имя файла пишите латиницей, без пробелов. Из него получится адрес страницы: `/lesson-2/2-3-box-model/`. Если файл-заглушка уже есть, откройте его и перенесите в него содержимое образца.

**2. Заполните верхнюю часть между строками `---`.** Это frontmatter — данные шага:

| Поле | Что писать |
|---|---|
| `title` | название шага, в кавычках |
| `lesson` | номер занятия из `src/data/route.json` (1–7) |
| `minutes` | сколько минут на шаг — из этого считается время маршрута |
| `goal` | цель одной строкой |
| `sidebar.order` | порядковый номер шага в занятии |
| `links` | 1–2 ссылки «если хочешь глубже» |
| `warmup` | разминка: `task` — задача, `html`/`css` — стартовый код, `checks` — автопроверки |
| `checklist` | пункты «готово» |
| `mistakes` | частые ошибки: `q` — проблема, `a` — что делать |
| `blocks` | готовые блоки по теме (`header`, `hero`, `cards` …) |
| `optional` | `true` — шаг можно пропустить, он не нужен для минимума |
| `fast` | «быстрый путь» для отстающих: какой готовый блок взять |
| `warmup.width` | ширина превью разминки в px, например `375` для шагов про телефон |
| `warmup.js` | стартовый JavaScript. Если поле есть (даже пустое), в песочнице появятся поле JS и консоль |
| `game` | мини-игра перед разминкой — см. ниже «Мини-игра» |
| `team` | «Кто что делает»: 4 задачи для участников по порядку частей сайта (шапка и подвал, первый экран, карточки, остальные секции — `src/data/parts.json`). У каждой `task` и `hint`. Блок ставится компонентом `<TeamTasks />` в конце «Делаем свой сайт» |
| `tableOfContents` | `false` — у шагов нет колонки «На этой странице» (так во всех шагах) |
| `topic` | тема в задачнике: `html`, `css`, `flex`, `grid`, `adaptive`, `js`. Для шагов её можно не писать — она берётся из занятия в `route.json` |

Если в файле есть строка `soon: true`, удалите её: она показывает плашку «Шаг ещё пишется».

Правила для верхней части:
- отступы делаются **пробелами**, не Tab. Вложенные поля сдвинуты на 2 пробела;
- если в тексте есть двоеточие `:`, возьмите весь текст в кавычки: `title: "Медиазапросы: 375 px"`;
- стартовый код разминки пишется после `html: |` с новой строки, с отступом.

**3. Автопроверки разминки.** Каждое правило — пункт списка в `checks`. В нём обязательно поле `fail`: что увидит ученик, если проверка не прошла.

```yaml
checks:
  - exists: ".cards"                      # элемент есть на странице
    fail: "Нет блока .cards"
  - selector: ".cards"                    # у элемента такой стиль
    style: { display: "grid" }
    fail: "У .cards пока нет display: grid"
  - count: { selector: ".card", min: 3 }  # элементов не меньше min
    fail: "Нужно хотя бы 3 карточки"
  - selector: ".card h3"                  # в элементе есть текст
    text: "Барсик"
    fail: "В заголовке нет клички"
  - selector: "img"                       # у элемента есть атрибут
    attr: "alt"
    fail: "У картинки нет alt"
```

В правиле `js` для JS-разминок можно нажимать кнопки: `doc.querySelector('.burger').click(); return doc.querySelector('.menu').classList.contains('open')`. Проверки идут в скрытой копии превью, поэтому ученик этих нажатий не видит. Пути к картинкам `img/…` в превью переписываются под адрес сайта, а исходный путь лежит в `data-src`.

В `style` браузер отдаёт «посчитанные» значения: размеры в `px` (`16px`, не `1rem`), цвета в виде `rgb(255, 0, 0)`, не `red`. Толщину рамки и ширину колонок `1fr` точным значением не проверяйте: браузер округляет их (рамка `2px` на экране с масштабом 125% станет `1.6px`). Для них есть правило `js` с допуском — примеры в шагах 2.3 и 4.1. Для сложных случаев есть правило `js` — это тело функции, которая получает документ `doc` и возвращает `true` или `false`. Примеры есть в `templates/step.mdx` и в шагах занятия 1.

**Мини-игра.** Поле `game`: 3–5 коротких уровней на 2–4 минуты, до разминки. Три типа, примеры всех трёх — в `templates/step.mdx`:

- `ghost` — «поставь фигурки на призраков», как Flexbox Froggy. В `html` — фигурки (`<i class="sp sp-frog"></i>`; спрайты: `cat`, `dog`, `frog`, `coin`, `star`, `flower`, `tree`, `pine` и др. из `src/lib/sprites.ts`). Ученик пишет CSS для `.board` (или для `selector` уровня). `target` — CSS-решение: на поле полупрозрачные «призраки» стоят там, куда их ставит `target`. Уровень пройден, когда каждая фигурка совпала со своим призраком. Если у следующего уровня тот же селектор, в `target` повторите и прошлые свойства, а в `start` — что уже написано в редакторе.
- `tags` — в `html` мини-страница, ученик кликает на нужную часть. `target` — селектор правильного элемента (`header`, `.card`).
- `quiz` — вопрос: `options` — варианты, `answer` — номер верного (с 1, на странице варианты перемешаются), `why` — объяснение. Без `options` ученик кликает строку в `code`, а `answer` — номер строки с ошибкой.

Пройденная игра записывается в прогресс (`games` в `nav-v1`), 10 игр дают значок «Игроман». Все игры собраны в «Задачнике» по темам.

**4. Напишите текст шага** под заголовками «Теория», «Разминка», «Делаем свой сайт». Порядок частей и компоненты (`<Warmup />`, `<Hint>` …) уже расставлены в образце. Меняйте только текст.

- Теорию оборачивайте в `<Npc> … </Npc>`: проводник Байт показывает её по репликам — каждый абзац, код или `<Preview>` отдельно. Кнопка «Показать всё» раскрывает всё сразу.
- Названия тегов и код внутри текста берите в обратные кавычки: `` `<header>` ``, `` `display: flex` ``. Знаки `<`, `>`, `{`, `}` без кавычек ломают страницу.
- Пример с живым превью: `<Preview html={`...`} css={`...`} />`. Код пишется между обратными кавычками.
- Подсказки и решение: `<Hint title="Подсказка 1">текст</Hint>`. На странице они открываются по очереди.
- Текст под кейс команды: `<ForCase id="tail">…</ForCase>` покажется только команде ХВОСТ_ДОМОЙ. `<ForCase>…</ForCase>` без `id` — общий текст для тех, кто кейс не выбрал или для чьего кейса варианта нет. Id кейсов: `watch`, `teammate`, `where`, `tail`, `split`.
- Пример с JavaScript: `<Preview html={`...`} js={`...`} />` — код выполнится в превью.
- Ссылки на другие страницы сайта делайте относительными: `../2-4-header-hero/`. Ссылки, которые начинаются с `/`, на GitHub Pages не сработают.

**5. Проверьте.** Запустите `npm run dev` и откройте шаг: пройдите игру (на верном ответе — монеты и «Все на месте!» / «Верно!»), введите в разминке верное решение, должна появиться зелёная плашка. Потом выполните `npm run build`: если в верхней части опечатка, сборка остановится и покажет файл и поле.

Шаг сам появится в боковом меню, на странице «Маршрут», в «Задачнике» и в плане занятия у модератора. Время пересчитается само. При сборке появится предупреждение `[маршрут] …`, если занятие не равно 80 минутам, весь маршрут длиннее 560 минут или у шага указано занятие, которого нет в `route.json`.

### Шаги без Node.js, прямо на GitHub

Файл можно создать и отредактировать в браузере: откройте папку на github.com → **Add file → Create new file** (или значок карандаша у существующего файла) → **Commit changes**. Сайт пересоберётся сам. Если во вкладке Actions появился красный крестик, откройте лог — там будет написано, что исправить.

## Где что лежит

```
src/content/docs/          страницы сайта
  lesson-1/ … lesson-7/    шаги занятий (один файл = один шаг)
  blocks/                  страницы готовых блоков
  tasks/                   задачник: index.mdx + дополнительные задачи (html-menu.mdx …)
  moderator/               раздел модератора: index.mdx (советы, критерии приёмки, чек-лист сдачи), sites.mdx (готовые сайты команд)
  index.mdx, route.mdx, cheatsheets.mdx
src/blocks/                код блоков (.html + .css, у burger, modal, filters ещё .js)
src/data/route.json        список занятий: номер, название, результат, минут на занятие
src/data/cases.json        кейсы и рекомендуемые блоки главной для каждого
src/data/blocks.json       список блоков (ready: false — «скоро»)
src/components/            компоненты шага: песочница, подсказки, чек-лист, Npc (проводник Байт), Game (мини-игры),
                           Island (3D-остров), Header / ThemeSelect / Footer (шапка, тема, подвал), HomeHero / LevelPath / Rules (главная)…
src/lib/                   прогресс (localStorage), автопроверки, подсчёт маршрута, sprites.ts (пиксельные спрайты),
                           fx.ts (конфетти), games/ghost.ts (игра «Призрак»), island.ts (3D-остров на three.js)
src/content.config.ts      какие поля бывают у шага
public/starter/            стартовый шаблон для команд (index.html, style.css, img/) и шаблон секции для работы вчетвером (section.html, section.css)
src/moderator-sites/       код готовых сайтов команд: <кейс>/index.html, style.css, script.js
public/mod-sites/          картинки готовых сайтов: <кейс>/img/
public/img/                картинки для примеров и разминок: img/barsik.svg и др.
templates/step.mdx         образец шага
```

**Новая задача в задачник:** скопируйте любой файл из `src/content/docs/tasks/`, например `css-button.mdx`, поменяйте `title`, `topic`, `sidebar.order`, разминку и подсказки. Задача сама появится в своей теме.

**Новый блок:** положите `имя.html` и `имя.css` (и, если нужно, `имя.js`) в `src/blocks/`, добавьте его в `src/data/blocks.json` с `"ready": true` и создайте страницу `src/content/docs/blocks/имя.mdx` по образцу `cards.mdx`.

**Оформление «Аркада 2.0»** (`src/styles/custom.css`): цвета — переменные `--a-*`, цвет мира — класс `.w-1` … `.w-7`. Объёмные кнопки — класс `a-btn` и варианты `a-btn--go`, `a-btn--coin`, `a-btn--pink`, `a-btn--sky`, `a-btn--big`; все кнопки в компонентах уже выглядят так. Шапка, переключатель темы и подвал — свои компоненты `Header.astro`, `ThemeSelect.astro`, `Footer.astro` (подключены в `astro.config.mjs` → `components`). Если добавите группу в боковое меню перед мирами, поправьте цветные точки «Мир N» в `custom.css` (`.sidebar-content .top-level > li:nth-child(...)`).

**3D-остров на главной** сделан на three.js. Конфетти — `canvas-confetti`. Других библиотек сверх Astro и Starlight нет. Он грузится только на главной и только если браузер умеет WebGL. Без WebGL на его месте ряд кнопок-миров.

**Профиль.** При первом заходе сайт просит создать профиль: имя, команда, кейс (или своя тема), роль (ученик или модератор) и часть сайта. Профиль хранится в браузере, поменять — кнопка с именем в шапке. Ученику не видно ссылок на раздел модератора.

**Раздел модератора закрыт кодом доступа.** Всё, что в `src/content/docs/moderator/` обёрнуто в `<ModSecret>…</ModSecret>`, при сборке шифруется (`src/integrations/moderator-lock.mjs`). Коды — в переменной `MODERATOR_CODES`, через запятую:
- локально — в файле `.env` (образец — `.env.example`, сам `.env` в гит не попадает);
- на GitHub — **Settings → Secrets and variables → Actions → New repository secret**, имя `MODERATOR_CODES`.

Выдать доступ — добавить код и пересобрать сайт (любой push или **Actions → Run workflow**). Забрать — убрать код и пересобрать. Модератор вводит код один раз, браузер его запоминает. В `npm run dev` раздел виден без кода — только у себя на компьютере.

**Готовые сайты команд** (`/moderator/sites/`) — главные страницы по макетам команд: превью «Компьютер / Телефон», код, «Открыть в новой вкладке» и «Скачать сайт (.zip)». Код сайтов попадает на сайт только в зашифрованном виде. Чтобы добавить сайт:
1. Положите `index.html`, `style.css`, `script.js` в `src/moderator-sites/<кейс>/`. В `index.html` подключайте их ровно так: `<link rel="stylesheet" href="style.css">` и `<script src="script.js"></script>` — превью подставляет код по этим строкам.
2. Картинки — в `public/mod-sites/<кейс>/img/`, в коде путь `img/имя.png`. Картинки лежат открыто, это не код.
3. Добавьте строку в массив `SITES` в `src/components/TeamSites.astro`: `id` (имя папки), кейс, название, подпись и ссылку на макет.

**Прогресс учеников** (выбранный кейс, пройденные шаги и игры, чек-листы, черновики разминок) хранится только в браузере, в localStorage, под ключом `nav-v1`. Сервера нет. Если хранилище отключено, сайт работает, но ничего не запоминает.
