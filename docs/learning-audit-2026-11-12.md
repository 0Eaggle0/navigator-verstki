### P1. Проверка 7.2 удаляет избранное

Правила в `lesson-7/7-2-localstorage.mdx` вызывают `localStorage.removeItem('favorites')`. `new Function('doc', ...)` исполняет правило в контексте навигатора; JS-превью и проверочный iframe используют то же хранилище origin.

Воспроизведение в отдельном профиле:

1. До открытия страницы записано `favorites = ["sharik"]` и контрольный ключ `audit-unrelated = keep`.
2. После открытия страницы `favorites` отсутствует; контрольный ключ сохранился.
3. Правильное решение получило зачёт. Клик в видимом превью по Шарику сохранил `["sharik"]`.
4. Добавление CSS-комментария перезапустило проверку; `favorites` снова отсутствует.

Исправление: отдельное управляемое состояние проверочных сценариев, без очистки пользовательского хранилища. Проверять восстановление после загрузки, обе карточки, переключение и сохранность ранее выбранного. Критерий: начальные данные навигатора и превью не меняются от выполнения проверок.

### P1. Игры не подтверждают самостоятельное решение

- В `Game.astro` ошибочный вариант не завершает попытку и не требует нового действия с кодом. Последовательный клик по видимым кнопкам прошёл все 43 вопроса и записал прохождение всех 10 quiz-игр.
- В `ghost.ts` CSS ученика вставляется в общий документ цели и игрового слоя. В поле CSS достаточно ввести `} .board>*{display:none} #play .board{`. Все фигуры имеют нулевые прямоугольники, `score()` принимает их совпадение. Это воспроизведено на всех 36 уровнях восьми игр без DevTools.
- В обычном прохождении цели достижимы: 36/36 CSS-решений из `target` приняты, стартовые состояния не дают автоматической победы. Переходы по уровням и итоговая запись `games` сработали на всех 18 страницах.

Исправление по плану: quiz-зачёт заменить практикой. Для CSS-игр отделить эталон от изменяемых учеником стилей и проверять наличие/видимость ненулевых фигур. Простого запрета одной конкретной строки недостаточно. Библиотека должна опираться на практику, а не эти игровые отметки.

### P2. Корректная функция отклоняется

В 6.1 код `const greet = n => 'Привет, ' + n + '!';` с именем, выводом в консоль и записью приветствия в `h1` получает только 1/3. Правила ищут исключительно `doc.defaultView.greet`, а глобальная `const` не является свойством `window`.

Исправление: проверять вызов функции в контексте ученического кода, а не наличие свойства `window`. Принимать объявление функции и стрелочную функцию; проверять минимум два разных аргумента, согласованность заголовка и результата, вывод в консоль.

### P2. Проверка незавершённой формы запускает отправку

В `tasks/js-form` оба правила вызывают настоящий `requestSubmit()`. Пока ученик не написал `preventDefault()`, адрес проверочного iframe становится `about:srcdoc?name=%D0%90%D0%BD%D1%8F`. Отдельное наблюдение подтвердило этот переход; HTTP-отправка на сервер не наблюдалась. Нельзя утверждать, что страница бесконечно перезагружается или задача нерешаема: правильное решение прошло.

Для браузерного аудита ожидание `networkidle` дважды завершалось тайм-аутом на этой странице. Проверка завершена после перехода к ожиданию DOM и результата самой песочницы, без блокировки навигации и без правок продукта.

Исправление: проверять отмену отменяемого события `submit` и результат обработчика без запуска настоящей навигации. Ошибка должна объяснять отсутствие `preventDefault`, а не менять документ проверки.

Нулевой код завершения аудита означает, что все сценарии выполнены и записаны, **а не что сайт не имеет ошибок**. Для последующих пунктов неверные решения из этого отчёта должны превратиться в отрицательные регрессионные проверки.
