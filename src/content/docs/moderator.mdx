## Как вести пару

- Одна пара = одно занятие маршрута, 80 минут. Шаги и время — в таблицах ниже, они собираются из файлов шагов автоматически.
- Начало шага (2–3 мин): прочитайте вслух цель, покажите пример из теории на проекторе.
- Разминку каждый делает сам, прямо на сайте. Зелёная плашка «Всё верно» — можно переходить к заданию «Делаем свой сайт».
- Подсказки открываются по очереди. Попросите открывать «Решение» только после двух подсказок.
- Раз в 20–30 минут обходите команды: пусть покажут чек-лист шага.
- В конце пары — 5 минут: команда показывает результат занятия на своём сайте.

## Если команда отстаёт

- Минимум проекта — занятия 1–5: свёрстанная адаптивная главная. Занятия 6–7 (JavaScript) — только если минимум готов.
- У многих шагов есть **быстрый путь** (синяя плашка под заголовком): взять готовый блок из раздела [Блоки](../blocks/) и поменять тексты и цвета. Лучше вставить и понять, чем застрять на час.
- Шаги с пометкой «можно пропустить» не нужны для минимума.
- Прогресс хранится в браузере конкретного компьютера. Если ученик пересел, отметки и черновики не переедут. Код проекта при этом в его папке, ничего не пропало.

## Как работать вчетвером над одним сайтом

Пока нет Git, у страницы один «главный» файл, а собирает его модератор (или один участник).

1. В занятии 1 распределите секции главной между участниками (шаг 1.1).
2. Каждый делает свою секцию в отдельном файле: `pets.html` + `pets.css`. Туда же он пишет медиазапросы для своей секции.
3. Все стили секции начинаются с её класса: `.pets h2`, `.pets .card`. Тогда стили разных людей не мешают друг другу.
4. В конце пары участники присылают файлы в общий чат, модератор вставляет HTML в `index.html` на нужное место, а CSS — в конец `style.css`.
5. Общие вещи (переменные, сброс, шрифты, `.container`) лежат в `style.css` у модератора, их правит только он.

## Критерии приёмки главной (минимум)

| Критерий | Как проверить |
|---|---|
| Семантические теги | В коде есть `header`, `main`, `section`, `footer`, меню в `nav`, один `h1` |
| Цвета и шрифты как в макете | Сравнить рядом с Figma; цвета в CSS-переменных |
| Нет горизонтальной прокрутки на 375 px | DevTools → режим устройства → 375 px, листать вбок |
| У картинок есть alt | В коде у каждого `img` непустой `alt` |
| Сайт открывается по ссылке | Ссылка на GitHub Pages работает с телефона |

## Чек-лист сдачи

- [ ] Все секции макета свёрстаны, тексты без «рыбы» и опечаток
- [ ] Семантические теги, один `h1`, заголовки по уровням
- [ ] Шрифты и цвета из макета, цвета в переменных
- [ ] На 1280 px страница похожа на макет, на 375 px нет прокрутки вбок
- [ ] У всех картинок есть `alt`, все ссылки и кнопки кликабельны
- [ ] У кнопок и ссылок есть `:hover`
- [ ] Сайт опубликован на GitHub Pages, ссылка открывается

## Как добавить или поменять шаг

1. Скопируйте образец `templates/step.mdx` в папку занятия, например `src/content/docs/lesson-6/6-1-script.mdx` (заглушки уже лежат там, их можно просто дописать).
2. Заполните верх файла между `---`. Уберите строку `soon: true`.
3. Напишите текст под заголовками «Теория», «Делаем свой сайт» и подсказки.
4. Проверьте, что сайт собирается: локально `npm run build` или вкладка Actions на GitHub.

Время маршрута пересчитается само. Если занятие не равно 80 минутам или весь маршрут длиннее 560 минут, при сборке появится предупреждение. Подробная инструкция — в `README.md` репозитория.
