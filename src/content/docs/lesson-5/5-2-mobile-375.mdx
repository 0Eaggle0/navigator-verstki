## Теория

<Npc>

Версию для телефона строят от главного правила: **ничего не должно быть шире экрана**. Горизонтальная прокрутка на телефоне — главный признак сломанного адаптива.

Что обычно меняют в медиазапросе:
- **Ряды → столбики.** Флекс-строке пишут `flex-direction: column`: первый экран «текст — картинка» становится «текст над картинкой».
- **Сетки → меньше колонок.** `grid-template-columns: 1fr` — одна колонка, `1fr 1fr` — две.
- **Размеры → меньше.** Крупные заголовки и большие отступы уменьшают, иначе на экран влезет одно слово.

Если сетка сделана через `repeat(auto-fill, minmax(…))`, медиазапрос ей не нужен: она перестроится сама. Но проверить всё равно нужно — минимальная ширина в minmax не должна быть больше 343 px (375 минус отступы).

## Делаем свой сайт

1. Откройте сайт в режиме устройства на 375 px.
2. Идите по списку поломок из шага 5.1 сверху вниз. Для каждой секции решите: что встаёт столбиком, сколько колонок у сеток, что уменьшить.
3. Всё пишите в один медиазапрос в конце `style.css`.
4. Прокрутите страницу вбок — если она двигается, найдите виновника (подсказка в «Частые ошибки»).
5. Проверьте ещё ширину 1024 px (планшет): там часто хорошо смотрятся две колонки.

<Hint title="Подсказка 1">
Делите работу: каждый участник проверяет на 375 px свою секцию и пишет для неё правила. Модератор собирает все в один медиазапрос.

<Hint title="Подсказка 2">
Большие отступы секций (`padding: 80px 0`) на телефоне съедают полэкрана. В медиазапросе уменьшите их вдвое: `section { padding: 40px 0; }`.
</Hint>

<Hint title="Решение">
```css
@media (max-width: 768px) {
  .header .container {
    flex-direction: column;
    gap: 12px;
  }

  .menu {
    flex-wrap: wrap;
    justify-content: center;
    gap: 12px 16px;
  }

  .hero .container {
    flex-direction: column;
  }

  .hero h1 {
    font-size: 32px;
  }

  .cards,
  .footer__cols {
    grid-template-columns: 1fr;
  }

  section {
    padding: 40px 0;
  }
}
```
